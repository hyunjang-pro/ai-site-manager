# v3.19 견적 엔진 구조 — 문장 → 일감 명세 → 4축 적산

> 이 문서는 v3.19에서 견적 분류·산출 엔진을 **케이스별 if 땜빵**에서 **구조화 적산 엔진**으로
> 바꾼 내용을 정리한 것이다. 새 문장이 들어와도 같은 규칙으로 처리되게 하는 것이 목적이다.

## 1. 왜 바꿨나 (예전 구조의 문제)

예전 `classify.js`는 공종마다 정규식을 문장 전체에 다시 돌리는 if 사슬이었다.

- 한 낱말이 공종을 독식했다 — `주방`이 나오면 뒤에 `타일`이 붙어도 주방(싱크대) 공사,
  `선반` 하나가 목공이었다가 부분 철거였다가 했다(파일마다 낱말 표가 달랐다).
- 철거만 하는 문장과 시공까지 하는 문장이 같은 규칙을 탔다
  (`장판 제거` → 도배 시공, `욕실 1칸 철거` → 올수리 641만).
- 같은 돈이 두 곳에서 더해졌다 — `laborTotal += …`가 여러 갈래에 흩어져 있어
  화면 합계와 항목 합계가 어긋나도 잡아낼 방법이 없었다.
- 단가가 `pricing.js`·`partial.js`·`site.js`에 흩어져 같은 품목을 다르게 계산했다.

## 2. 지금 구조

```
문장
 └ engine/text.js      절 나누기 · 한글 수사·단위 정규화 · 숫자+단위 추출
 └ engine/parse.js     절 안에서 품목·동작·수량을 **짝짓기** (인접어 판단)
 └ engine/jobspec.js   4가지 의도 모드 → 공종 → 규모 → 세부 공종 → 현장 조건
 └ engine/ledger.js    줄(line)마다 4축(자재·인건비·장비·폐기물) 하나 · 합계는 줄에서 재계산
 └ engine/rate-book.js 품목 단가표(SSOT) — 축별로 쪼갠 값
 └ engine/surcharge.js 현장 조건 할증 규칙표 (층수·시간·거리·장비·규제)
 └ pricing.js          위 재료로 줄을 만들고 마진·가격·일수만 계산
```

### 2-1. 의도 모드 (jobspec.js)

| 모드 | 판단 | 예 |
|---|---|---|
| `labor` 인력 지원 | 사람 수 + 직종 + (지원·일당·N일), 규모(평·㎡) 없음 | "철거 인력 3명 2일" |
| `bid` 관공서 공고 | 예정가·기초금액·입찰 문구 | "안동시 ○○ 철거공사" |
| `part` 단독 부분 교체 | 동작이 하나뿐이고 `~만`으로 한정 | "주방 상판만 교체" |
| `general` 일반·복합 | 나머지 | "24평 아파트 도배 장판" |

모드는 공종을 정하기 **전에** 정한다. 그래서 "사람 3명만 보내줘 철거"가 15평 철거 325만으로
튀지 않고, "상판만 교체"가 싱크대 전체 교체 541만으로 튀지 않는다.

### 2-2. 품목 사전 (engine/lexicon.js) — 낱말은 한 곳에만

품목마다 `scope`(공종) · `role`(scope/sub/object/space) · `authority`(공종 지목 강도) ·
`unit`·`defaultQty` · `partialId`(부분 철거 품목)를 적는다.

- **동작이 자기 공종을 들고 온다** — `도장`은 어디에 붙어도 도장(repair)이다.
  그래서 "문짝 도장"이 목공이 아니라 도장, "베란다 샷시 도장"이 창호 교체가 아니다.
- **authority가 가장 높은 품목이 공종을 정한다** — "주방 벽 타일 15㎡"는 타일,
  "주방 상판만 교체"는 주방.
- **단위가 뜻을 좁힌다** — "욕실 1칸 타일"은 욕실(칸), "욕실 타일 20㎡"는 타일(면적).
- **표면 공사** — 도장·필름·코킹의 대상(문짝·샷시·싱크대)은 별도 공종이 아니라 대상이다.
  "아파트 34평 샷시 문짝 싱크대 필름 리폼"은 필름 한 건이다.

### 2-3. 인접어 파서 (engine/parse.js)

1. 절을 나눈다 — 쉼표·`+`·`/`·줄바꿈·접속 조사. `·`는 품목 목록이라 끊지 않는다.
2. 품목·동작을 찾고 **동작은 품목 뒤쪽(한국어 어순)부터** 짝짓는다.
   품목 이름 자체가 동작이면(도배·필름·방수) 그 동작이다.
3. 수량은 **단위가 맞는 가장 가까운 숫자**를 쓰되, 다른 품목에 더 가까운 숫자는 넘겨준다.
   `34평`을 조명 개수로 읽지 않는다.
4. 부정·제외를 먼저 걷어낸다 — "철거는 안 하고", "창호 제외".
5. 동작이 없는 절은 이웃 절의 동작을 물려받되, 물려받은 동작을 '묶인 것'으로 세지 않아
   "철거 + 부지 정지"가 복합으로 남는다.

### 2-4. 4축 적산 (engine/ledger.js + rate-book.js)

모든 금액은 **한 줄에 한 축**만 갖는다.

- 축: `material` 자재 · `labor` 인건비 · `equip` 장비 · `waste` 폐기물
- 합계는 누산기가 아니라 **줄의 합**이다 → 같은 돈이 두 축에 겹칠 수 없다.
- `pricing.js`는 별도 `laborTotal += …`를 하지 않고, `axisTotals`를 줄에서 다시 센다.
  (테스트가 `Σ4축 = 원가` 불변식을 확인한다)
- 단가표(`RATE_BOOK`)는 뭉친 값을 축별로 쪼개 적는다. 예: 욕실 타일 60만/칸 = 자재 35 + 인건비 25.

### 2-5. 현장 조건 할증 (engine/surcharge.js)

규칙표 한 곳에 조건·금액·축·반영방식을 적는다.

| 조건 | 반영 |
|---|---|
| 엘리베이터 없음·지하·반지하 | 양중(인력 반출·사다리차) + 자재 올리기 |
| 2층 이상 부피 큰 반출 | 사다리차 반나절/하루 (층별 범위) |
| 8층 이상 | 사다리차 상위 구간, 15층 이상 고층 구간 |
| 야간·심야 | 작업시간 제한 +20만 |
| 주말·공휴일 | 인건비의 10% (최소 5만) |
| 안동 외 출장 | 20만 |
| 장비(굴삭기·포크레인) | 하루 20㎡ 작업량으로 환산 |
| 거주 중·보양·관리소 신고·준공 청소 | 현장 성격에 따라 자동 포함 |

## 3. 상가 원상복구 시세 중간값 반영

기존 엔진은 큰 평수에서 인력 일수를 3명·3일로 끊어 **평당 16만원대**까지 내려갔다.
지방(안동) 상가 원상복구 시세는 평당 22~25만원(중간 23)이다.

- `RATE_BOOK.demolition.restoreLaborPerPyung = 11` — 상가·사무실·매장의 원상복구/전체 철거에서
  인건비를 **평당 11만원 하한**으로 잡는다. (부대비용·폐기물을 더하면 고객가 평당 23~25만)
- 적용 대상은 **상가·사무실·매장·식당·카페·학원·병원·공장·창고·노래방·가게** 등의
  원상복구·전체 철거다. 주거(아파트) 마감 철거(평당 17~19만), 마감재 한 가지 철거,
  칸막이·간판 같은 품목 철거에는 적용하지 않는다.

| 현장 | v3.18 | v3.19 | 평당 |
|---|---|---|---|
| 상가 15평 원상복구 | 346만 | 392만 | 26.1만 |
| 카페 20평 원상복구 | 348만 | 468만 | 23.4만 |
| 식당 30평 원상복구 | 485만 | 664만 | 22.1만 |
| 사무실 12평 원상복구 | 465만 | 299만 | 24.9만 |
| 32평 아파트 철거 | 575만 | 575만 | 18.0만 (변동 없음) |
